# Прототип Telegram Mini App

`prototype.html` — кликабельный визуальный прототип. Один файл, без сборки и без
внешних запросов: открывается двойным кликом в браузере или отдаётся как есть.
Данные внутри — константы; сети нет.

Это макет интерфейса, а не работающее приложение. Кода бота он не трогает.

## Что покрыто

| Экран | Что заменяет в боте |
|---|---|
| Прогноз | `/today`, `/tomorrow`, выбор дня из обзора, кнопка «Ветер по высотам», «Разбор от ИИ», метеограмма |
| Обзор | `/threedays`, `/week`, `/twoweeks`, `/scan` (режим «Все старты») |
| Маршрут | `/route`, `/saveroute`, `/routes`, карточка точки, разрез, перебор времени вылета, разбор ИИ |
| Настройки | `/model`, `/settings`, `/sites`, `/add`, `/removesite`, доступ и пауза между запросами |

Шторки: ветер по высотам, метеограмма, карточка точки, разбор дня, разбор
маршрута, выбор старта, выбор модели, сохранённые маршруты, новый маршрут,
добавление старта.

## Решения, которые стоит обсудить до кода

**Палитра не выдумана.** Взята из `charts.py`: шкала оценок — `GRADE_RGB`,
рельеф — `TERRAIN`, рабочий коридор — `BAND`, ряды графиков — `TEMP`/`WIND`/`GUST`.
Так PNG из бота и экраны приложения читаются как одна система, а не как два
разных продукта. Цвета рядов держатся отдельно от шкалы лётности: путать «жёлтый
= удовлетворительно» и «жёлтый = такая-то температура» нельзя.

**Контекст живёт в шапке, а не в сообщении.** Старт, дата и модель всегда на
экране; тело перерисовывается под ними. Это и есть ответ на «в чате история
быстро засирается»: возврат к прогнозу не создаёт новое сообщение.

**Два прибора вместо карточки с большим числом.** День читается по двум осям:
полоса часов (время, высота столбика = балл, цвет = категория) и столб воздуха
(высота: рельеф → старт → рабочий коридор → потолок → база). Балл стоит рядом
мелко — пилот летает окно, а не число.

**Разовая и постоянная модель разделены явно.** Верхний чип показывает, чем
посчитан текущий экран, и подписан «разово», когда он расходится с постоянной.
Потолок отдельной строкой сказано, что всегда по GFS.

**Причина ограничения вытесняет описание погоды.** В строках обзора и скана обе
не помещаются; «ограничивает: порывистость» полезнее, чем «перем. обл.».

## Чего в прототипе намеренно нет

- Реальных тайлов карты. Рельеф рисуется генеративно на canvas — внешние
  запросы всё равно заблокированы, а для оценки макета тайлы не нужны.
- Валидации `initData`, HTTP-слоя, авторизации. Это backend, его в макете нет.
- Настоящих чисел open-meteo. Данные правдоподобные, но выдуманные; форматы
  повторяют `engine.report_1day`, `route._rows`, `route.render_point_card`,
  `engine.wind_grid`.

## Проверка

```
node --check   # синтаксис скрипта (см. историю ветки)
```

Скриншоты снимались headless-Chrome при ширине 452 CSS-px в обеих темах.
Тема переключается тумблером над макетом; по умолчанию берётся системная.
