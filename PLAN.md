# PLAN: тупиковые ветки логики (по ревью 2026-07-24)

Ветка: `feature/logic-deadends`

## Находки ревью → фиксы

1. [x] **Длинное имя старта ломает inline-клавиатуры** (callback_data > 64 байт → Telegram отклоняет всё сообщение, для `/today` без аргумента — полная тишина).
   - Валидация имени в `/add` (one-shot и интерактивный шаг): ≤ 40 байт UTF-8 (~20 кириллических символов), без символа `|` (ломает парсинг callback_data).
   - Защита при сборке кнопок: хелпер, который молча (с warning в лог) пропускает кнопку, чей callback_data не влезает в 64 байта — для уже существующих длинных имён.
2. [x] **Геолокация-пин в ответ на «Пришли координаты» — тишина**: хендлеры `F.location` для состояний `AddSite.coords` и `AdHoc.coords`.
3. [x] **Старые кнопки (>48 ч) → `InaccessibleMessage` → падение без ответа**: guard в начале каждого callback-хендлера — «Кнопка устарела», show_alert.
4. [x] **Тишина на нераспознанный ввод** (в т.ч. после рестарта с потерей FSM): catch-all `@dp.message()` последним — подсказка на /help.
   - Ад-хок точка после рестарта: в `forecast._resolve` распознавать имя-координаты и отвечать понятно («точка больше не в памяти, запроси заново»), а не «Старт не найден».
5. [x] **Десятичная запятая в координатах → молча другая точка**: парсер координат через regex-токены чисел (поддержка `42,47 44,48`, `42.47, 44.48`); ≠ 2 числа → переспросить, а не брать первые попавшиеся.
6. [x] **Day-picker в таймзоне сервера, а не старта**: даты кнопок брать из кэшированных фактов обзора (реальные даты open-meteo, timezone=auto); фолбэк на серверное «сегодня» при холодном кэше. Плюс guard в `cb_pick_day`: прошедшая дата → «кнопка устарела».
7. [x] **Липкое состояние `AdHoc.coords`**: сбрасывать его, если юзер вместо координат нажал кнопку выбора старта/дня; упомянуть /cancel в переспросе координат.
8. [x] **Имя нового старта = alias существующего → недостижимая запись**: `engine.add_site` проверяет и имена, и alias'ы.
