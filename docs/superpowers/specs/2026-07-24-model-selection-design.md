# Выбор метеомодели (`/model`) — дизайн

**Дата:** 2026-07-24
**Ветка:** `feature/model-selection`

## Запрос пользователя

Добавить возможность выбора метеорологической модели. По умолчанию — ECMWF.

## Эмпирическая проверка (open-meteo, ecmwf_ifs025)

Прямой запрос к open-meteo подтвердил: ECMWF отдаёт **всё, что нужно боту, кроме
двух переменных** — `boundary_layer_height` и `freezing_level_height` (приходят
`null` по всем часам). Барические уровни (925/850/700/600/500 hPa: скорость,
направление, геопотенциал), порывы, температура, влажность, облачность, CAPE,
осадки — присутствуют. Значит деградация нужна ровно в двух местах: потолок
термиков и уровень замерзания. Всё остальное (метеограмма, профиль ветра, сетка
«ветер по высотам», обзоры) работает на любой из выбираемых моделей.

## Согласованные продуктовые решения

- **Модели** (ключ пользователя → id open-meteo для `&models=`):
  - `auto` → `best_match`
  - `ecmwf` → `ecmwf_ifs025` — **дефолт**
  - `gfs` → `gfs_seamless`
  - `icon` → `icon_seamless`
- **Выбор** — командой `/model` (персистентный глобальный дефолт), без inline-кнопок.
- **Дефолт ECMWF** с аккуратной деградацией: где нет потолка/уровня замерзания —
  показывать «н/д», график потолка пропускать.

## Архитектура

Ложится на существующие слои: `bot.py` (`/model`) → `forecast.py` (кэш с ключом
по модели) → `engine.py` (URL + хранение модели + деградация отчёта) + `charts.py`
(условный график потолка). Модель — глобальная настройка (как `sites.json`,
единый файл, разделяемый всеми whitelisted-пользователями).

### 1. `engine.py` — реестр моделей, хранение, URL

**Реестр** (единый источник — метка для UI + id open-meteo + ключ команды):

```python
MODELS = {  # ключ → (метка для UI, open-meteo id)
    "auto":  ("Auto (best_match)", "best_match"),
    "ecmwf": ("ECMWF",             "ecmwf_ifs025"),
    "gfs":   ("GFS",               "gfs_seamless"),
    "icon":  ("ICON",              "icon_seamless"),
}
DEFAULT_MODEL_KEY = "ecmwf"
```

**Хранение** — маленький JSON рядом с `sites.json`, в том же writable-каталоге
(в контейнере — том). Путь: `MODEL_FILE = os.environ.get("MODEL_FILE") or
<dir(SITES)>/model.json`. Начальное значение при отсутствии файла — env
`DEFAULT_MODEL` (ключ) или `DEFAULT_MODEL_KEY`.

- `get_model_key() -> str` — читает ключ из `model.json` (или дефолт); если ключ
  невалиден/файл битый → дефолт.
- `set_model_key(key)` — валидирует по `MODELS`, пишет `model.json`
  (`{"model": key}`); ошибка записи пробрасывается (обрабатывается в боте, как `/add`).
- `model_id(key)` / `model_label(key)` — из `MODELS`.

**URL** — `build_url` добавляет `&models=<model_id(get_model_key())>` и в 1d, и в
обзорах. Все переменные запрашиваются как прежде — недоступные у модели просто
приходят `null` (open-meteo не падает).

### 2. `engine.py` — деградация отчёта (только blh + freezing)

Добавить утилиту:
```python
def _series_available(H, key):
    """True если переменная реально пришла (не отсутствует и не сплошь null)."""
    v = H.get(key)
    return bool(v) and any(x is not None for x in v)
```

**`report_1day`:** вычислить `has_blh = _series_available(H, "boundary_layer_height")`.
- Если `has_blh`: как сейчас (top_agl/top_msl/blue/график потолка/рабочий слой).
- Если нет: не считать потолок/blue; строка «🧗 Потолок: н/д (модель не даёт)»;
  «🔆 Термичка» — по CAPE (`max(cape[i]) > 20`); **не** вызывать `ceiling_png`;
  `profile_png` вызвать в режиме без полосы рабочего слоя.

**`facts_1day`:** `thermal_ceiling_m_agl/_msl`, `lcl`-зависимый `blue`,
`freezing_level_m` → `None`, когда переменных нет. Добавить поле
`"model": model_label(get_model_key())` в `facts["site"]` (или верхнеуровнево).

**Карточка (обе ветки):** добавить в шапку/подвал строку источника, напр.
`· модель: {model_label}` — отвечает и на вопрос «какая модель».

Обзоры (`report_overview`, `overview_rows`, `facts_overview`) blh не используют —
не трогаем.

### 3. `charts.py` — условный/устойчивый рендер

- `ceiling_png` вызывается только когда blh есть (решает `report_1day`).
- `profile_png` — сделать полосу «потолок рабочего слоя» условной: если blh нет,
  рисовать профиль без полосы/подписи рабочего слоя (параметр или проверка
  доступности blh внутри). Профиль скоростей по высотам сам по себе от blh не
  зависит.
- `meteogram_png`, `wind_grid_png`, `overview_png` — blh не используют, без изменений.

### 4. `forecast.py` — ключ кэша по модели

Ключ `_fcache`/`_acache` дополняется текущей моделью, чтобы смена модели не
отдавала старый кэш. `_resolve` включает `get_model_key()` в кортеж-ключ:
`(site_name, rng, date, model_key)`. Соответственно обновляются места, строящие
ключ (`cached_dates`, `get_wind_grid`, `scan_week`, `get_analysis`'s `acache_key`).
`facts` в кортеже значения остаётся на своём индексе (контракт 7-кортежа не
меняется — меняется только КЛЮЧ словаря, не значение).

### 5. `bot.py` — команда `/model`

- `/model` без аргумента → текущая модель + список ключей с метками
  (напр. «Текущая: ECMWF. Доступно: auto · ecmwf · gfs · icon»).
- `/model <ключ>` → `engine.set_model_key`; подтверждение «Модель: ECMWF».
  Невалидный ключ → ошибка со списком. Ошибка записи файла → понятное сообщение
  (как в `_finish_add`).
- Регистрация в `BOT_COMMANDS` и `HELP`.
- Флаг `forecast` для `/model` НЕ ставить (это настройка, не запрос прогноза; не
  должно попадать под кулдаун прогноза).

## Крайние случаи

- Неизвестный ключ в `/model` → ошибка со списком валидных.
- `model.json` недоступен на запись → сообщение как у `/add`; чтение битого файла
  → дефолт (не падать).
- Модель без потолка (ECMWF): карточка/факты деградируют, график потолка не шлётся.
- Смена модели при тёплом кэше → отдаётся свежий результат (ключ включает модель).
- Модель, у которой нет и других переменных, теоретически → `_series_available`
  универсально защищает только blh/freezing (подтверждено, что у Auto/ECMWF/GFS/ICON
  барические уровни и порывы есть; blh отсутствует только у ECMWF).

## Вне рамок

- Inline-кнопки переключения модели под прогнозом (выбрали `/model`).
- Per-user модель (настройка глобальная, как `sites.json`).
- Сравнение двух моделей в одном ответе.
