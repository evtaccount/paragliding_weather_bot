# Ветер по высотам × часам — дизайн

**Дата:** 2026-07-24
**Ветка:** `feature/wind-grid`

## Запрос пользователя

После прогноза на день должна быть кнопка дозапроса данных по силе ветра.
Ответ — таблица (картинка), где строки по вертикали — изменение высоты,
столбцы по горизонтали — изменение времени, в ячейках — сила и направление ветра.

## Согласованные продуктовые решения

- **Формат:** картинка (PNG). Рендерится нативно, не зависит от markdown-разметки
  Telegram (которая в текущем боте не включена — сообщения шлются без `parse_mode`).
- **Уровни высоты (строки):** те же 6, что уже тянет однодневный запрос —
  10 м / 925 / 850 / 700 / 600 / 500 hPa.
- **Шаг по времени (столбцы):** каждый час, за светлое время (sunrise..sunset).
- **Направление во всех ячейках:** в запрос добавляются `wind_direction_600hPa`
  и `wind_direction_500hPa` (для 10м/925/850/700 направление уже есть).
- **Скрывать уровни ниже старта:** показываются только уровни на высоте старта и
  выше, плюс один ближайший уровень ниже старта — для контекста. Число строк
  плавает по высоте старта (для Гудаури 2685 м уйдут 925/850, для низкого старта
  останутся все шесть).

## Архитектура

Фича ложится на существующие слои: `bot.py` (хендлеры) → `forecast.py`
(кэш+оркестрация) → `engine.py` (детерминированный расчёт) + `charts.py` (PNG).
Кнопка опциональна (как разбор ИИ) — данные для сетки извлекаются из уже
загруженного ответа open-meteo, PNG строится по требованию, без повторного запроса.

### 1. `engine.py`

**Расширение запроса.** В `H_1D` добавить `wind_direction_600hPa` и
`wind_direction_500hPa` (те же 6 уровней, +2 поля). URL для 1d вырастает на 2 поля;
на карточку/факты/LLM это не влияет.

**Новая функция `wind_grid(data, site) -> dict`.** Чистый локальный расчёт из
`data` (тот же объект open-meteo, что и `report_1day`):

- Опорный час — полдень светлого времени (середина `daylight_idx`), как в
  `profile_png`, для стабильных высот уровней.
- Уровни-кандидаты (снизу вверх по геопотенциалу опорного часа):
  - `10m` — высота `elev + 10`, направление `wind_direction_10m`;
  - `925/850/700/600/500 hPa` — высота из `geopotential_height_<lvl>hPa` опорного
    часа, скорость `wind_speed_<lvl>hPa`, направление `wind_direction_<lvl>hPa`.
- **Отбор строк относительно старта** (`launch = elev`): взять все уровни с
  `alt_m_msl >= launch`, плюс один ближайший уровень с `alt_m_msl < launch` (с
  максимальной высотой среди нижних) для контекста. 10 м (поверхность старта)
  входит всегда. Отсортировать по высоте по возрастанию.
- Часы — `daylight_idx(t, sunrise, sunset)`, каждый час.
- Для каждого уровня — почасовой ряд `{hour, wind_ms, dir_deg}` (`dir_deg` есть у
  всех 6 уровней после расширения запроса).

Возвращает:

```python
{
    "date": "YYYY-MM-DD",
    "timezone": "Asia/Tbilisi",
    "launch_m": 2685,
    "hours": [8, 9, 10, ...],
    "levels": [   # снизу вверх
        {"label": "10 м", "alt_m_msl": 2695, "is_launch": True,
         "hourly": [{"hour": 8, "wind_ms": 2.1, "dir_deg": 175}, ...]},
        ...
    ],
}
```

`is_launch` — у уровня `10m` (поверхность старта), для подсветки строки/линии.

### 2. `charts.py`

**Новая функция `wind_grid_png(grid, site, out) -> str`.** Рисует сетку в
существующем стиле (палитра, `_wind_arrow`, светлая тема, supersampling):

- Заголовок: `{site} — ветер по высотам × часам {date}`, подпись
  `стрелка — откуда · скорость м/с · {timezone}`.
- Строки — уровни (сверху вниз: высокие сверху), слева подпись `{alt} м` (у
  10 м — `10 м / старт`). Строка старта выделена (лёгкая заливка/рамка).
- Столбцы — часы, сверху подпись `HH`.
- Ячейка: фон по силе ветра (порог ниже), стрелка направления (`_wind_arrow`,
  откуда, N вверх) + число скорости `{wind_ms:.0f}`.
- **Пороги цвета ячейки (м/с, ветер на высоте):** `<= 6` зелёный (`GOOD`),
  `6–10` жёлтый (`WARN`), `> 10` красный (`RAIN`) — с прозрачностью ~46, как в
  существующих заливках. Легенда снизу: три цвета с подписями + «стрелка — откуда».
- Ширина холста подстраивается под число часов (`~64 px` на столбец, минимум как у
  прочих графиков), высота — под число уровней.
- Имя файла: `05_windgrid.png`.

### 3. `forecast.py`

**Кэш.** Кортеж `_fcache` расширяется 7-м элементом `grid` (по аналогии с
`rows`, добавленным для `/scan`):
`(expires, card, pngs, facts, fallback, rows, grid)`. `facts` остаётся на индексе 3
→ `cached_dates` (читает `entry[3]`) не ломается. Для 1d `grid =
engine.wind_grid(data, site)`; для обзоров `grid = None`.

- `_fetch_build` возвращает `card, pngs, facts, fallback, rows, grid`.
- `_ensure` кладёт/возвращает 6 значений (`card, pngs, facts, fallback, rows, grid`).
- Существующие распаковки обновить на 6 элементов:
  `get_forecast` (`card, pngs, _facts, _fallback, _rows, _grid`),
  `get_analysis` (`card, _pngs, facts, fallback, _rows, _grid`),
  `scan_week.fetch` (`_c, _p, _f, _fb, rows, _grid`).

**Новая `get_wind_grid(site_name, date) -> bytes`.** Через `_resolve` +
`_ensure` берёт тёплый (или строит) 1d-кэш, извлекает `grid`. Если `grid is None`
(например уровней над стартом нет — вырожденный случай) → `ForecastError`
(«Данные по высотам недоступны»). Иначе строит PNG через `charts.wind_grid_png`
во временной директории и возвращает байты (как `_fetch_build` — `read_bytes`,
`shutil.rmtree`). Строится по требованию, чтобы обычный `/today` не платил за
неиспользуемую картинку.

### 4. `bot.py`

**Кнопка.** В `send_forecast`, при `rng == "1d"`, добавить кнопку
`🌬 Ветер по высотам` с callback `wg|{site}|{date}`. Проверка 64 байт — через
`_btn` (имя ≤ 40 байт → `wg|` + имя + `|` + дата ≤ 57 байт, влезает). Кнопку
разместить в той же inline-клавиатуре, что и разбор ИИ, отдельной строкой
(сообщение «Нужен разбор от ИИ?» остаётся; клавиатура: строка кнопок разбора +
строка `[🌬 Ветер по высотам]`). Для обзоров кнопки нет.

**Хендлер `cb_wind_grid`** (`F.data.startswith("wg|")`, `flags={"forecast": True}`):
те же guard-ы, что у `cb_pick_day`:

- `cb_message` — устаревшее (>48 ч) сообщение → alert «Кнопка устарела».
- Разбор `wg|site|date`; кривой `callback_data` → тихий `cb.answer()`.
- Прошедшая дата (`< today - 1 день`) → alert «Эта дата уже прошла».
- `cb.answer("Считаю ветер по высотам…")`; затем `get_wind_grid`, отправка фото
  (`answer_photo(BufferedInputFile(...))`). Ошибки `ForecastError`/прочие → как в
  `cb_analysis`, сообщением пользователю.
- Клавиатуру не трогаем (пользователь может нажать снова / другой разбор).

## Крайние случаи

- **Высокий старт** (Гудаури): 925/850 ниже старта — уйдут; останутся 700/600/500
  над стартом + 10 м (поверхность) + один ближайший нижний уровень для контекста.
- **Низкий старт** (Лалискури 900 м): все 6 уровней ≥ старта или около — покажутся.
- **Кривой/устаревший callback, прошедшая дата** — те же guard-ы, что у `pd|`.
- **Длинное легаси-имя старта** (> 40 байт): `_btn` вернёт `None`, кнопка тихо
  выпадет, карточка дойдёт (как для кнопок разбора).
- **Холодный кэш** (нажали `wg|` после рестарта, кэша нет): `_ensure` сам загрузит
  1d-данные и построит `grid` — сеть будет, но результат корректен.

## Вне рамок

- Баг «сырые `**` в разборе ИИ» (Telegram не рендерит markdown, т.к. нет
  `parse_mode`) — отдельная задача, по слову пользователя.
- Текстовый вариант таблицы (`<pre>`), двухчасовой шаг, добавление промежуточных
  барических уровней — отклонены на этапе дизайна.
