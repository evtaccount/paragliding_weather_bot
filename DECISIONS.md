# DECISIONS — тупиковые ветки логики

- **64-байтный лимит callback_data решаем валидацией имени в `/add`** (≤ 40 байт UTF-8, без `|`),
  а не короткими ID/токенами в callback_data: токены жили бы в памяти и умирали при рестарте
  (кнопки в чате живут дольше процесса). Для уже сохранённых длинных имён — защитный пропуск
  кнопки с warning в логе, чтобы одно имя не убивало всю клавиатуру.
- **Координаты парсим regex-токенами чисел** с поддержкой десятичной запятой; ровно 2 числа,
  иначе переспрос. «42,47 44,48» = 42.47/44.48, а «42 47 44 48» — ошибка, не первые два числа.
- **Ад-хок точки после рестарта не восстанавливаем** (elevation пришлось бы тянуть синхронно
  в `_resolve`) — вместо этого понятное сообщение «запроси заново через 📍 По координатам».
- **Day-picker строится из дат кэшированного обзора** (site-local, из ответа open-meteo),
  серверное «сегодня» — только фолбэк при холодном кэше.
- **Состояние `AdHoc.coords` сбрасывается кнопками выбора старта/дня** — юзер передумал;
  состояние `AddSite.*` кнопками НЕ сбрасываем (терять прогресс /add из-за случайного тапа хуже).
- **Catch-all отвечает только подсказкой на /help**, без эха и угадывания намерений.
